# FreightFlow AI: Disruption Prediction & Recovery

> **Predict, Negotiate, Recover** — An autonomous cross-party logistics disruption mitigation platform powered by multi-agent negotiation.

---

## 📌 Problem Overview: The Cascade Today

In multimodal freight logistics, ports, trucking carriers, and destination warehouses operate in silos with fragmented schedules coordinated primarily via phone calls, manual emails, and static spreadsheets. 

When a disruption strikes early in the chain:
1. **Port Delay:** Cargo is ready at 2:00 PM instead of scheduled 10:00 AM.
2. **Truck Idles:** Carrier truck arrives at the scheduled hour, waits idly, and burns driver duty limits.
3. **Missed Dock Slot:** The downstream warehouse intake appointment is forfeited.
4. **Cascaded Failure:** Demurrage fees compound, customer delivery SLAs fail, and significant monetary value (₹) is jeopardized.

Existing market tools (such as visibility aggregators or siloed TMS/WMS) provide alerts but lack automated, multi-party collaborative recovery mechanisms. **FreightFlow AI bridges this gap with proactive risk scoring and decentralized agent negotiation.**

---

## 💡 Proposed Solution

FreightFlow AI deploys a **Central Coordinator and three autonomous domain agents** (Carrier Agent, Port Agent, and Warehouse Agent) that negotiate collaboratively across constraints:

- **1. Proactive Risk Prediction:** A machine learning risk engine (`scikit-learn`) flags emerging delay probabilities early before delays ripple downstream.
- **2. Cascade Impact Mapping:** A directed dependency graph (`NetworkX`) traces downstream bottlenecks and quantifies total financial exposure (₹ at risk).
- **3. Scripted Multi-Agent Negotiation:** A 2-to-3 round offer/counter-offer negotiation protocol where agents exchange operational constraints without exposing confidential internal cost structures.
- **4. Pareto-Ranked Recovery Plans:** Generates the Top 3 feasible recovery options:
  - 🟢 **Cheapest Plan:** Minimizes financial penalties and reschedule fees.
  - ⚡ **Fastest Plan:** Minimizes customer delay and transit downtime.
  - 🛡️ **Safest Plan:** Maximizes buffer time and schedule reliability.
- **5. Human-in-the-Loop & LLM Explanation:** A clean Streamlit interface presents the options alongside plain-English trade-off explanations generated by an LLM, prompting human approval before committing schedule updates.

## 🛠️ Technology Stack

| Layer | Technology | Purpose |
| :--- | :--- | :--- |
| **Frontend** | Streamlit, Plotly | Interactive operations dashboard, cascade dependency view, and approval UI |
| **Backend** | Python 3.10+ | Central coordinator, agent decision logic, and orchestrator |
| **Storage** | SQLite + SQLAlchemy | Operational database for shipments, schedules, slots, disruptions, and plans |
| **ML Risk Model** | scikit-learn, Pandas, NumPy | Delay probability classification and regression trained on synthetic signals |
| **Cascade Graph** | NetworkX | Directed dependency graph modeling and ₹ at risk propagation |
| **AI / LLM** | Google Gemini / OpenAI API | Text-to-event structured extraction and natural language plan explanation |
| **Agent Comms** | Python Function Calls / Contracts | Clean, deterministic scripted protocol (no external message broker required) |

## 🔄 End-to-End Workflow

```
[ Disruption Signal ]
        │
        ▼
[ 1. Risk Scorer (scikit-learn) ]
        │ High Risk Detected?
        ├─ No ──► Continue Monitoring
        └─ Yes
            │
            ▼
[ 2. Cascade Dependency Graph (NetworkX) ]
        │ Maps affected bookings & ₹ at risk
        ▼
[ 3. Central Coordinator Opens Recovery ]
        │
        ├─ Round 1: Initial Offers from Carrier, Port & Warehouse Agents
        ├─ Round 2: Counter-Offers with Shared Constraints
        └─ Round 3: Final Offers & Feasibility Evaluation
            │
            ▼
[ 4. Pareto Ranking: Top 3 Feasible Plans ]
        │ Cheapest | Fastest | Safest
        ▼
[ 5. Human-in-the-Loop Approval & LLM Explanation ]
        │ LLM summarizes trade-offs; human operator clicks approve
        ▼
[ 6. Operating Schedules Update (SQLite) ]
        │ Before / After timeline reflected across all party dashboards
```

## 📊 Evaluation & Benchmarking (50 Simulated Disruption Runs)

The system includes a dedicated benchmarking harness to prove algorithmic efficacy over **50 randomized disruption scenarios** against a standard **First-Come, First-Served manual baseline**:

1. **Delay Reduction (%)**: Percentage decrease in end-to-end customer delivery delay.
2. **Truck Waiting Time (Hours)**: Reduction in non-productive driver and truck idle hours.
3. **Transport & Penalty Costs (₹)**: Financial savings from avoided detention and overtime surcharges.
4. **Conflicts Resolved**: Rate of successfully negotiated conflict-free slot realignments.

## 🚀 Quick Start Guide

### 1. Prerequisites & Environment Setup
Clone the repository and set up a Python virtual environment:

```bash
# Navigate to the project root
cd Freight_Flow_AI

# Create and activate virtual environment
python3 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt
```

### 2. Configure Environment Variables
Copy `.env.example` to `.env` and set your optional API keys:

```bash
cp .env.example .env
```

### 3. Initialize & Seed Database
Populate SQLite with initial mock supply chain records:

```bash
python3 src/database/seed_data.py
```

### 4. Run CLI Pipeline Dry-Run
Execute a simulated disruption through the orchestrator:

```bash
python3 src/main.py
```

### 5. Launch the Streamlit Dashboard
Start the interactive UI:

```bash
streamlit run src/dashboard/app.py
```
